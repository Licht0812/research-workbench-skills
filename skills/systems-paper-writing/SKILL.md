# Systems Paper Writing

Own systems-specific argument and prose when selected, preserving actual design, implementation status, and evaluation evidence.

## Workflow

1. Identify the target workload, bottleneck, design insight, system boundary, implemented components, and intended scientific claim.
2. Connect motivation to a measured or source-backed problem, then explain design choices, alternatives, assumptions, and implementation details needed for reproduction.
3. Organize evaluation around the claims: end-to-end outcomes, component ablations, overheads, scalability within available resources, and relevant stress cases.
4. Revise the requested artifact in its existing format; verify current venue requirements only when format/submission details matter.

Preserve the supplied findings and source format; distinguish evidence gaps from requested prose edits.

Read [the workflow reference](references/workflow.md) when implementation decisions or validation details are needed.

## Deliverable

Requested systems-paper text, a coherent claim/evidence structure, and specific unresolved evaluation gaps.
